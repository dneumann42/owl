#+TITLE: Owl Language Specification

Owl is a small interpreted language in which every form is a [[term-command][command]] call. A command is given its [[term-argument][arguments]] as unevaluated syntax and evaluates whichever of them it needs, so constructs that are normally built into a parser — =if=, =else=, =for=, =record=, list and record construction — are written in Owl instead. They live in the prelude — the source file =owl/prelude.owl= — which the [[term-evaluator][evaluator]] evaluates before running a program.

Linked terms are defined in [[*References][References]], along with a pointer to the code that implements them.

* Syntax
[[term-indent][Indentation]] groups statements into [[term-block][blocks]] and can spread one call's arguments across several lines. Parentheses group an [[term-expr][expression]] written on a single line.

** Tokens
The [[term-lexer][lexer]] converts source text into tokens. It drops horizontal whitespace, comments, and blank lines, and produces newline, indent, and dedent tokens. [[*String Interpolation][String interpolation]] is expanded at this stage.

*** Special Characters
| characters         | meaning                                                                       |
|--------------------+-------------------------------------------------------------------------------|
| space, tab, =CR=, =LF= | whitespace; leading whitespace produces indent and dedent tokens              |
| =;=                  | starts a comment, which runs to the end of the line                           |
| =,=                  | separates forms written on one line                                           |
| =(= =)=                | group a form; =)= also closes any indentation opened inside the group           |
| =[= =]=                | together form the symbol =[]=; also delimit the index selector =.[= ... =]=         |
| =.=                  | starts a selector, except between two digits, where it belongs to a number    |
| =:=                  | starts a [[term-block][block]]                                                                |
| ~=~                  | separates a [[term-binding][binding]] name from its value; alone, it names the equality command |
| ="=                  | delimits text                                                                 |
| =\=                  | escape character inside text; ~\(~ starts an interpolation                      |

*** Lexical Constants
| constant        | definition                                                                                   |
|-----------------+----------------------------------------------------------------------------------------------|
| =atom=            | =atom_start= followed by any number of =atom_char=                                               |
| =atom_start=      | any non-whitespace character except =(= =)= =[= =]= ="= =.= =,= =:= ~=~ =;=                                      |
| =atom_char=       | as =atom_start=, except that ~=~ is allowed and =.= is allowed between two digits                  |
| identifier-like | an atom starting with a letter or underscore, continuing with letters, digits, =_=, =-=, =?=, or =/= |
| numeric         | an atom starting with a digit, or with =+= or =-= followed by a digit                            |
| =operator_symbol= | an atom that is neither identifier-like nor numeric, such as =+=, =[]=, or ={}=                    |
| =string_char=     | any character except ="=, =\=, =CR=, or =LF=                                                         |
| =NL=              | =LF=, =CR=, or =CR LF=                                                                             |
| =END=             | =NL=, or the position just before =DEDENT=, =)=, or =EOF=                                            |
| =INDENT=          | produced when leading whitespace increases; a tab counts as eight columns                    |
| =DEDENT=          | produced when leading whitespace decreases                                                   |
| =EOF=             | end of file                                                                                  |

Dedenting to a column that does not match an enclosing indentation level is an error. A =)= closes any indentation opened after its =(=, so a group can be closed on the last line of its own indented block.

** Grammar
#+begin_src ebnf
script          = stmts, EOF .
stmts           = { NL | stmt } .
stmt            = form, (layout_tail | { ",", form }, END) .

layout_tail     = ":", suite | argument_block .
suite           = NL, INDENT, stmts, DEDENT .
argument_block  = NL, INDENT, { NL | argument_item, { argument_item }, END }, DEDENT .

form            = binding | expr .
binding         = atom, "=", (expr | suite) .
expr            = string, selectors | command .
command         = callee, { inline_argument } .

callee          = symbol_like, selectors | group .
inline_argument = (argument_primary | same_line_layout_argument), selectors .
argument_primary
                = symbol_like | string | group .
same_line_layout_argument
                = operator_symbol, ":", suite .
argument_item   = (layout_item | argument_primary), selectors .
layout_item     = (symbol_like | group), layout_tail .

group           = "(", form, [ layout_tail ], stmts, ")", selectors .
selectors       = { ".", (atom | "[", form, "]") } .

symbol_like     = atom | "=" | "[", "]" .
string          = DQUOTE, { string_char | escape | interpolation }, DQUOTE .
escape          = BS, (DQUOTE | BS | "n" | "r" | "t") .
interpolation   = BS, "(", form, ")" .
#+end_src

A [[term-binding][binding]] whose value is a =suite= holds a [[term-script][script]]: the statements are evaluated in order, and the value of the last one becomes the binding's value.

A [[term-group][group]] contains one form, an optional [[term-layout-tail][layout tail]], and any further [[term-statement][statements]] before the closing parenthesis. This is what allows an =if=/=else= pair to be written as one parenthesized expression.

** Layout
Indentation following a form attaches to it in one of two ways, recorded on the command node as its [[term-layout-kind][layout kind]].

A colon attaches a [[term-block][block]]. The indented statements are passed to the command unevaluated, and what happens to them is up to that command.

#+begin_src owl
when (> count 0):
  print "some"
  print " left"
#+end_src

Indentation without a colon attaches [[term-argument][arguments]] instead. Each indented line contributes one or more arguments, so a call can be spread over several lines rather than parenthesized.

#+begin_src owl
print
  +
    1
    2
    3
  " and "
  T
#+end_src

That parses as =print (+ 1 2 3) " and " T=. A [[term-binding][binding]] can also put its value on the following indented lines:

#+begin_src owl
define:
  world = +
    1 2 3
  total =
    -
      10
      1
#+end_src

A comma separates forms on one line, so ~1, 2, 3~ is three statements.

When a colon follows an argument on the same line, the argument's token class determines which command the colon belongs to. After an identifier-like or numeric argument the colon belongs to the enclosing command, which is why =if condition:= and =block-command name:= keep their blocks. After an =operator_symbol= the colon belongs to that argument, so =print []:= is a call to =print= with one argument: the =[]= command with a block. Parenthesizing the operator symbol gives the colon back to the enclosing command, as in =block-command ([]):=.

** Selectors
The [[term-parser][parser]] turns a selector into a call. =a.b= parses as =field a "b"=, and =a.[k]= parses as =index a k=. Selectors chain, so =a.b.c= and =a.[+ 1 2].d= produce nested calls to those same two commands. =set= treats a selector as an assignment target; see [[*Environments And Assignment][Environments And Assignment]].

** String Interpolation
~\(~ inside text starts an interpolation. The [[term-lexer][lexer]] reads up to the matching =)=, tokenizes the text between them as Owl source, and expands the whole string into a =concat= call with each interpolated form wrapped in =to-string=.

#+begin_src owl
define:
  hello = + 1 2 3
  message = "Compute: \(+ hello 4)"
#+end_src

Finding the end of an interpolation is a parenthesis count, and nested text is not excluded from it: every =(= and =)= is counted, including ones inside a quoted string. ~"\(concat "(" ")")"~ works because those two cancel out, while ~"\(concat "(" "x")"~ is an error. An interpolation also cannot span a line.

~\\~ is an escaped backslash, so ~"a\\(b)"~ is the five-character text ~a\(b)~ and not an interpolation.

* Values
Evaluating a [[term-syntax-node][syntax node]] produces a [[term-value][value]]. There are ten kinds:

#+CAPTION: Runtime Values
| kind    | contents                                       |
|---------+------------------------------------------------|
| nothing | no payload                                     |
| number  | 64-bit floating point number                   |
| boolean | =true= or =false=                                  |
| text    | a string of bytes                              |
| stream  | input or output marker for host extensions     |
| list    | ordered values                                 |
| record  | text keys to values                            |
| syntax  | a syntax node and the environment it came from |
| command | a native command or an Owl [[term-closure][closure]]             |
| native  | host-provided extension value                  |

Only =nothing= and =false= are [[term-truthiness][falsey]]. Every other value is [[term-truthiness][truthy]], =0= and =""= included.

The =stream= kind is a marker a host program can pass in; Owl never produces one itself. Owl's own streams are records, described under [[*Streams And Resources][Streams And Resources]].

** Text Form
=to-string value= converts a value to text. For numbers, booleans, text, lists, and mutable records the result is Owl source that evaluates back to an equal value. Commands, host values, and immutable records have no source form and convert to a readable stand-in instead: =<command>=, =<native>=, and ={x: 1}=.

Several commands are defined in terms of this conversion: ~=~ compares two values by their text form, =error= builds its message from it, and =print= and the stream write commands use it for every kind except text, which they write as it is.

** Numbers
Every number is a 64-bit float. Dividing by zero produces =inf= rather than an error. A number with no fractional part converts to text without a decimal point, so =+ 1 2= gives =3= while =/ 3 2= gives =1.5=.

A number literal starts with a digit, or with =+= or =-= followed by a digit, and may contain a decimal point or an =e= exponent.

** Text
Text is written between double quotes. It cannot contain a line break; write ~\n~ instead. The escapes are ~\"~, ~\\~, ~\n~, ~\r~, ~\t~, and ~\(~ for an [[*String Interpolation][interpolation]].

=length text= returns a byte count, not a character count. =concat= joins text values.

** Lists
A list is an ordered sequence of values. =append= and =pop-front= modify a named list in place, which is what keeps repeated appending from copying the whole list each time. Every other list command returns a new list and leaves its input unchanged.

=list= returns an empty list. The =[]= command evaluates each statement in its block and returns a list of the results.

#+begin_src owl
define:
  empty = (list)
  values = []:
    1, 2, 3
append values 4
write-line stdout (to-string values.[0])
#+end_src

** Records
A record maps text keys to values. Records come in two forms. A mutable record can gain new keys at any time. An immutable record has a fixed set of keys, decided when its type is declared. In both cases =set= can replace the value stored under a key that already exists.

=dict= returns an empty mutable record, and the ={}= command builds one from a block of [[term-binding][bindings]]. Any text key can be added to a mutable record with =set= or =dict-put=.

#+begin_src owl
define:
  config = {}:
    name = "owl"
    answer = (+ 40 2)
set config.["extra"] 7
set config (dict-put config "name" "barn")
write-line stdout (to-string config.answer)
#+end_src

=record Name:= declares an immutable record type. The block is a list of [[term-binding][bindings]] giving the field names and their default values. The declaration defines two commands in the scope where it was written: =Name=, which constructs a record, and =Name?=, which returns true for records built by that declaration. Two declarations under different names produce different types even when their fields are identical.

=Name= takes field values as positional arguments, as a block of bindings, or as both. A default is evaluated only when the call does not supply that field.

#+begin_src owl
record Vec3:
  x = 0
  y = 0
  z = 0

define:
  a = (Vec3 1 2 3)
  b = Vec3 1 2:
    z = 4
  c = Vec3
    5
    6
    7
set b.z 40
write-line stdout (to-string (Vec3? a))
#+end_src

Assigning to a key an immutable record does not have is an error, as is passing the constructor an unknown field name or more arguments than the type has fields.

An immutable record converts to text with its fields in declaration order: ={x: 1, y: 2, z: 3}=. A mutable record converts to a ={}= call with its keys sorted, or to a chain of =dict-put= calls when one of its keys is not identifier-like.

* Evaluation
A new [[term-evaluator][evaluator]] creates a [[term-root-env][root environment]], installs its native commands there, and evaluates the prelude in it. Programs then run in that environment. A host program can install native commands and modules of its own.

** Node Evaluation
Evaluating a [[term-script][script]] evaluates its statements in order; the value of the script is the value of its last statement. An empty script evaluates to =nothing=.

A [[term-string][string]] evaluates to text.

A [[term-binding][binding]] does not assign anything on its own. Evaluating one produces a =syntax= value containing the binding node and the current [[term-env][environment]], which commands such as =define=, ={}=, and =record= then interpret. A binding written as a statement by itself has no effect.

A [[term-symbol][symbol]] is evaluated in this order:

1. A symbol that parses as a number evaluates to that number.
2. =true= and =T= evaluate to the true boolean.
3. =false= and =F= evaluate to the false one.
4. Otherwise the symbol is [[term-lookup][looked up]] in the [[term-env][environment chain]]. An unbound symbol is an error.

** Symbols And Command Calls
Whether a symbol is read or called depends on where it appears.

As an [[term-argument][argument]], a symbol evaluates to the value bound to it, whatever that value is.

As a [[term-statement][statement]], as a [[term-callee][callee]], or inside parentheses, a symbol is a command call with no arguments: if the bound value is a command it is called, and otherwise the value is returned unchanged. So =x= reads a variable while =x 1= calls the command stored in =x=, and =(next)= calls an iterator while =next= written as an argument passes the command itself along. =value-of name= returns the command bound to a name without calling it.

In every other call the [[term-callee][callee]] expression is evaluated first and must produce a command value. The command is then given the unevaluated [[term-argument][argument]] nodes, the [[term-layout-kind][layout kind]], and the [[term-block][block]]; evaluating any of them is up to the command. This is the [[term-call-protocol][command call protocol]].

** Commands
There are two kinds of [[term-command][command]].

A [[term-native-command][native command]] is a procedure in the host language. It is called with:

| input       | meaning                                          |
|-------------+--------------------------------------------------|
| environment | the [[term-caller-env][caller environment]]                           |
| arguments   | unevaluated [[term-argument][argument]] syntax nodes                |
| layout      | [[term-layout-kind][=NoLayout=, =ColonLayout=, or =ContinuationLayout=]] |
| body        | the syntax nodes in the [[term-block][block]]                       |

A native command performs its own [[term-arity][arity]] and type checks and evaluates only the arguments it needs, which is what lets =and= and =or= [[term-short-circuit][short-circuit]].

A [[term-closure][closure]] is a command written in Owl. It stores its [[term-parameter][parameter]] names, the syntax of its body, and the environment it was defined in.

| constructor                       | parameters receive | takes a block |
|-----------------------------------+--------------------+---------------|
| =fun name parameter...=             | evaluated values   | no            |
| =fn parameter...=                   | evaluated values   | no            |
| =command name parameter...=         | unevaluated syntax | no            |
| =block-command name parameter...=   | unevaluated syntax | yes           |

=lambda= is another name for =fn=, and =component= for =command=. =fn= and =lambda= return an anonymous command rather than defining a name.

A call must supply exactly as many arguments as the closure has parameters. Giving a block to a closure that does not take one is an error.

When a closure evaluates its arguments, the [[term-call-scope][call scope]] is a child of the environment the closure was defined in, and each [[term-parameter][parameter]] is [[term-binding-value][bound]] to an evaluated argument. When it takes [[term-raw-syntax][unevaluated syntax]], the call scope is a child of the [[term-caller-env][caller environment]] instead, and each parameter is bound to a =syntax= value pairing the argument node with the caller's environment.

A call also binds these two names, but only when the closure's body mentions them and has no [[term-parameter][parameter]] of the same name:

| name   | value                                        |
|--------+----------------------------------------------|
| block  | a syntax value holding the block as a [[term-script][script]] |
| layout | the [[term-layout-kind][layout kind]] as text                      |

The body is evaluated in the [[term-call-scope][call scope]], and the value of its last statement is the result of the call.

** Environments And Assignment
An [[term-env][environment]] is a table of bindings with an optional parent. Looking up a symbol searches the current environment, then each parent in turn, and finally the [[term-command-env][command environment]].

=define= evaluates each [[term-binding][binding]] in its block and binds the name in the current environment. It writes only there: rebinding a name that already exists in the same environment is an error, while a name bound in an enclosing environment is shadowed rather than modified.

A binding's value may be an indented block of statements, which are evaluated in order; the last value becomes the binding's value.

=set= changes an existing binding. Given =set target value= it evaluates the value first, then assigns it:

- If =target= is a [[term-symbol][symbol]], the innermost environment holding that symbol is updated. Assigning to an unbound symbol is an error.
- If =target= is a selector — a =field= or =index= call with two arguments — the container is rebuilt with the new value, and that container is then assigned back through this same rule. This is how =set point.y 100= and =set xs.[0] 20= work, nested selectors included.
- Otherwise =target= is evaluated and must produce a [[term-syntax-value][syntax value]] naming a symbol. The assignment happens in the [[term-capture][environment stored with that syntax value]].

Given a block instead, =set:= takes only [[term-binding][bindings]] and updates each named symbol.

The arithmetic assignment commands ~+=~, ~-=~, ~*=~, and ~/=~ take a symbol bound to a number and one number. They update the binding and return the new value.

*** Command Environment
The [[term-command-env][command environment]] is a single environment shared by every command, for state that has to outlive one call. Each [[term-evaluator][evaluator]] has one, and it is the last environment searched during [[term-lookup][lookup]], so reads and =set= reach it from any scope.

=command-define= evaluates each [[term-binding][binding]] in the caller's environment and binds the name in the command environment.

The prelude uses it for the statement form of =if=: =if= pushes its condition result onto a stack kept there, and =else= pops it. Since =else= always directly follows its =if=, nested pairs stay independent — an inner pair pushes and pops entirely inside the outer block.

** Modules
=use name= loads a module and binds it. If the host program registered a module under that name, that module is used. Otherwise =name= is a file path, with =.owl= appended when it has no extension. Relative paths resolve against the file the =use= is written in, so they do not depend on the working directory.

A file module is evaluated in its own child [[term-env][environment]], and its top-level bindings become a record bound under the file's base name. =use name alias= binds it under =alias=.

#+begin_src owl
use math-extra
use math-extra m
write-line stdout (to-string (math-extra.square 5))
write-line stdout (to-string (m.cube 2))
#+end_src

Given a block of filters, =use= binds the selected names directly in the current environment and returns =nothing=. =only= and =include= list names to bind; =except= and =exclude= list names to skip. Filters cannot be combined with an alias.

#+begin_src owl
use math-extra:
  only square
#+end_src

=import "path"= evaluates another file's statements in the current environment and returns the value of the last one, without building a record. Its argument is text, not a module symbol.

=eval-file path= and =eval-source source [path]= also evaluate in the current environment, but use their path as given instead of resolving it against the current file. =parse source= produces a [[term-syntax-value][syntax value]] without evaluating anything.

** Syntax Values
A [[term-syntax-value][syntax value]] pairs a [[term-syntax-node][syntax node]] with the [[term-env][environment]] it came from. Keeping both is what makes [[term-raw-syntax][unevaluated syntax]] predictable to work with: the syntax is evaluated where it was written, not where it was passed.

=eval= evaluates each argument. If the result is a syntax value, that syntax is then evaluated in the environment stored with it, or in the [[term-caller-env][caller environment]] if it has none. Anything that is not syntax is returned unchanged.

=parse= parses text into a syntax value paired with the caller's environment.

*** Syntax Inspection
These commands read [[term-syntax-value][syntax values]] as data.

| command                       | returns                                                       |
|-------------------------------+---------------------------------------------------------------|
| =statements script=             | a list of syntax values, one per statement                    |
| =body-of script tag=            | the block of the first statement calling =tag=, as script syntax |
| =command-arg command index=     | the syntax of one argument, by position                       |
| =command-symbol command=        | the callee name of a command called through a symbol          |
| =command-body command=          | the block of a command, as script syntax                      |
| =binding-symbol binding=        | the name a binding introduces                                 |
| =binding-value binding=         | the syntax of the value a binding assigns                     |
| =symbol-text symbol=            | the text of a symbol                                          |
| =eval-with symbol value body=   | evaluates body syntax in a child scope with one extra binding |

=body-of= returns an empty script when no statement matches the tag, rather than failing.

=define-caller-value name value= binds a value in the calling environment, given either a symbol syntax value or a text name. Together with =eval-with= it is what lets a command written in Owl introduce a name — a loop variable, for instance — in its caller.

** Errors
An evaluation error carries a [[term-source-context][source position]] and a [[term-stack-trace][stack trace]]. As the error propagates, a [[term-diagnostic-frame][diagnostic frame]] is recorded for each syntax node it passes through, except [[term-script][script]] nodes. A frame is labelled with the callee text for a command, the binding name for a binding, the symbol text for a symbol, and =string= for a string.

The innermost position is the one reported. The report contains the message, the source line it occurred on, and the frames from the outermost call inward.

#+begin_example
example.owl:6:3: error: cannot add record field: z
    set point.z amount
    ^
Stack trace:
  at owl/cli.owl:27:1 in when
  at owl/cli.owl:28:3 in eval-file
  at example.owl:11:1 in shift
#+end_example

The =owl/cli.owl= frames come from the command-line driver, which is itself written in Owl.

=error value...= raises an error whose message is its arguments in [[*Text Form][text form]]. =assert condition= raises when the condition is [[term-truthiness][falsey]], and otherwise returns it.

* Standard Commands
=standard-commands= returns Org-formatted documentation for the native commands, and =owl --std= prints it. The commands below are the ones Owl is normally written with. Those that are not native are defined in the prelude.

** Control Flow
=if=, =else=, =cond=, =not=, =do=, =for=, =[]=, ={}=, =record=, and the iterators are prelude commands, not [[term-parser][parser]] constructs. The evaluator supplies only what they are built from: =when=, =while=, =pick=, the closure constructors, and the data and syntax commands.

=when condition:= evaluates its block once if the condition is [[term-truthiness][truthy]] and returns the block's last value, or =nothing=.

=while condition:= evaluates the condition before each pass and repeats the block while it stays truthy. It returns the value of the last pass, or =nothing= if the block never ran.

=pick condition then else= evaluates the condition and then only the branch it selects. =not value= returns the opposite [[term-truthiness][truthiness]]. =do:= evaluates a block where an expression is expected.

=and= evaluates its arguments left to right and returns the first [[term-truthiness][falsey]] one, or the last one if all of them are truthy; with no arguments it returns =true=. =or= returns the first truthy argument, or the last one if none are; with no arguments it returns =false=.

=if condition:= and a following =else:= are expressions. =if= returns its block's value when the condition is truthy. =else= returns the =if='s value if the condition was truthy, and otherwise evaluates and returns its own block. The pair can be parenthesized wherever one expression is required:

#+begin_src owl
define:
  answer = (if ready:
    "yes"
  else:
    "no"
  )
#+end_src

=cond:= takes =when condition:= and =| condition:= clauses, evaluates their conditions in order, and returns the block of the first truthy one. An =else:= clause runs when none of them matched.

#+begin_src owl
define:
  size = (cond:
    when (< x 2):
      "small"
    | (< x 10):
      "medium"
    else:
      "large"
  )
#+end_src

** Iterators
An iterator is a [[term-command][command]] that takes no [[term-argument][arguments]] and returns the next value each time it is called, or =nothing= once it is exhausted. Iterators are a convention rather than something the evaluator implements.

| command                | yields                                    |
|------------------------+-------------------------------------------|
| =range start stop=       | =start= up to but not including =stop=        |
| =countdown start stop=   | =start= down to but not including =stop=      |
| =iter list=              | each item of the list                     |
| =once value=             | the value, then nothing                   |

=for name iterator:= evaluates the iterator expression once, then evaluates its block for each value produced, with =name= bound to that value in a child [[term-scope][scope]]. It returns the value of the last pass, or =nothing= if the iterator produced none.

#+begin_src owl
define:
  sum = 0
for n (range 1 5):
  += sum n
#+end_src

=for-each name iterator body= is the same loop with the body passed as a [[term-syntax-value][syntax value]] argument instead of a block. =for= is built from it.

** Arithmetic And Comparison
=+=, =-=, =*=, and =/= take one or more arguments, evaluate them as numbers, and [[term-fold-left][fold left]]. =floor= returns the largest integer that is not greater than its argument. The arithmetic assignment commands are described under [[*Environments And Assignment][Environments And Assignment]].

| command | returns                                             |
|---------+-----------------------------------------------------|
| ~=~       | whether both arguments have the same [[*Text Form][text form]]      |
| ~<~       | whether the left number is less than the right      |
| ~<=~      | whether the left is less than or equal to the right |
| ~>~       | whether the left number is greater than the right   |
| ~>=~      | whether the left is greater than or equal           |

Because ~=~ compares [[*Text Form][text form]], it accepts any two values: =1= equals =1.0=, and ="1"= does not equal =1=.

** List Commands
| command                 | returns                                                   |
|-------------------------+-----------------------------------------------------------|
| =list=                    | an empty list                                             |
| =cons value list=         | a new list with the value in front                        |
| =first list=              | the first item; the list must not be empty                |
| =rest list=               | everything after the first item, or an empty list         |
| =empty? list=             | whether the list has no items                             |
| =nth list index=          | the item at a position                                    |
| =append-value list value= | a new list with the value on the end                      |
| =drop-front list count=   | a new list without the leading items                      |
| =append list value=       | =nothing=; adds to the end of a named list in place         |
| =pop-front list count=    | =nothing=; drops leading items from a named list in place   |
| =list-from syntax-list=   | a list of the values a list of [[term-syntax-value][syntax values]] evaluates to |

=[]:= is built from =list-from=. =length= returns the number of items.

** Record Commands
| command                   | returns                                                           |
|---------------------------+-------------------------------------------------------------------|
| =dict=                      | an empty mutable record                                           |
| =dict-put record key value= | the record with one key updated                                   |
| =dict-get record key=       | the value at a text key; a missing key is an error                |
| =field record key=          | the same as =dict-get=, under the name the =a.b= selector calls       |
| =index value key=           | a list item by position, or a record value by text key            |
| =dict-from syntax-list=     | a mutable record built from a list of [[term-binding][binding]] syntax values       |
| =length value=              | the number of keys in a record, items in a list, or bytes in text |

={}:= is built from =dict-from=. =dict-put= works on an immutable record only for a key it already has.

=record-constructor= and =record-predicate= are the native commands behind =record Name:=; they build its constructor and its =Name?= predicate.

** Streams And Resources
=Stream= is an immutable record type declared in the prelude. Its fields are commands: =open=, =close=, =read=, =read-line=, =read-all=, =write=, and =write-line=. Every stream has all seven fields; the operations a given stream does not support raise an error when called.

=stdin= and =stdout= are =Stream= records in the [[term-root-env][root environment]]. Streams built by the host are =Stream= records too, so =Stream?= returns true for them.

=open-file path mode= returns a file-backed stream. Given only a mode, it uses a scratch file in the temporary directory. The modes are =r=, =rb=, =w=, =wb=, =a=, and =ab=. =open-string text= returns a stream over a text buffer.

The prelude commands =close=, =read=, =read-line=, =read-all=, =write=, and =write-line= call the matching field on a stream passed to them. =read= returns one byte as text, or =nothing= at end of input. =read-all= returns the rest of the input.

=with resource name:= evaluates the resource, calls its =open= field, binds the result under =name= in a child [[term-env][environment]], evaluates the block there, and calls =close= afterwards, including when the block raises. If =open= or =close= is missing, or returns =nothing=, the original resource value is used.

#+begin_src owl
with (open-string "line one\nline two") s:
  write-line stdout (read-line s)
#+end_src

** Program And Environment
=print value...= writes its arguments to standard output with no trailing newline. =to-string value= converts a value to [[*Text Form][text]]. =concat text...= joins text values.

=command-line-arguments= returns the program's arguments as a list of text. =exit [code]= terminates the program. =repl= reads, evaluates, and prints lines until =q=, =quit=, or end of input.

The =owl= binary is driven by =owl/cli.owl=: =owl= with no arguments starts the repl, =owl run <path>= evaluates a file, =owl --eval <source>= evaluates text, and =owl --std= prints the command reference.
