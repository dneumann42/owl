* Syntax

My goal with the syntax is to make it maximally useful, nicely expressive yet very simple. The syntax leverages [[term-indent][indentation]] to separate [[term-block][blocks]] and group [[term-expr][expressions]].

My goal with the syntax is to keep it as minimal yet useful as possible, indentation was chosen was the means to group expressions, optionally you can group expressions by surrounding them in '(' and ')'
** Tokens
- Token :: Single part of a program.
The [[term-lexer][lexer]] produces tokens before the [[term-parser][parser]] builds syntax nodes.
*** Special token characters:
| characters            | class                                         |
|-----------------------+-----------------------------------------------|
| ' ', '\t', '\r', '\n' | Whitespace                                    |
| ';'                   | Starts a comment                              |
| ','                   | Separates forms written on one line           |
| '(' ')'               | Used for grouping calls                       |
| '[' ']'               | Empty list symbol and selector index grouping |
| '.'                   | Starts a selector                             |
| ':'                   | Starts a code block                           |
| '='                   | Used for assignment                           |
| '"'                   | String start and terminal (refer to escaping) |
| '\'                   | String escape; =\(= opens an interpolation    |
*** EBNF
The [[term-lexer][lexer]] discards horizontal spacing, comments, and physical blank lines. It emits newline, indent, and dedent tokens for the [[term-parser][parser]].
#+begin_src ebnf
script          = stmts, EOF .
stmts           = { NL | stmt } .
stmt            = form, (layout_tail | { ",", form }, END) .

layout_tail     = ":", suite | argument_block .
suite           = NL, INDENT, stmts, DEDENT .
argument_block  = NL, INDENT, { NL | argument_item, { argument_item }, END }, DEDENT .

form            = binding | expr .
binding         = symbol, "=", (expr | suite) .
expr            = string, selectors | command .
command         = callee, { inline_argument } .

callee          = symbol_like, selectors | group .
inline_argument = (argument_primary | same_line_layout_argument), selectors .
argument_primary
                = symbol_like | string | group .
same_line_layout_argument
                = operator_symbol, ":", suite .
argument_item   = (layout_item | argument_primary), selectors .
layout_item     = (symbol_like | group), layout_tail .

group           = "(", form, [ layout_tail ], stmts, ")", selectors .
selectors       = { ".", (symbol | "[", form, "]") } .

symbol_like     = symbol | "=" | "[", "]" .
symbol          = atom .
string          = DQUOTE, { string_char | escape | interpolation }, DQUOTE .
escape          = BS, (DQUOTE | BS | "n" | "r" | "t") .
interpolation   = BS, "(", form, ")" .
atom            = atom_start, { atom_char } .
#+end_src

A [[term-binding][binding]] whose value is a =suite= is an expression script: the forms evaluate in
order and the last value is the binding's value.

A [[term-group][group]] holds one form, optionally a [[term-layout-tail][layout tail]], and then any further
statements before the closing parenthesis. This is what lets an =if=/=else= pair
be written as a single grouped expression.

An =interpolation= is scanned to its matching =)=, so parentheses and quoted
strings nest inside it. =\\\\= is an escaped backslash, so ~"a\\\\(b)"~ is the literal
text =a\\(b)= and not an interpolation.

Lexical constants:

| constant          | definition                                                                                                                |
|-------------------+---------------------------------------------------------------------------------------------------------------------------|
| =operator_symbol=   | a =symbol_like= that is neither identifier-like nor numeric                                                                 |
| identifier-like   | starts with a letter or underscore, and continues with letters, digits, =_=, =-=, =?=, or =/=                                     |
| =atom_start=        | any non-whitespace char except double quote, parentheses, brackets, dot, comma, colon, equals, or semicolon               |
| =atom_char=         | any char except whitespace, double quote, parentheses, brackets, comma, colon, or semicolon; dot only between two digits  |
| =string_char=       | any char except =DQUOTE=, =BS=, =CR=, or =LF=                                                                                     |
| =END=               | =NL=, or the position before =DEDENT=, =)=, or =EOF=                                                                              |
| =NL=                | =LF=, =CR=, or =CR LF=                                                                                                          |
| =INDENT=            | indentation token emitted when leading whitespace increases                                                               |
| =DEDENT=            | indentation token emitted when leading whitespace decreases                                                               |
| =EOF=               | end of file                                                                                                               |
| =DQUOTE=            | double quote                                                                                                              |
| =BS=                | backslash                                                                                                                 |
| =CR=                | carriage return                                                                                                           |
| =LF=                | line feed                                                                                                                 |
| comment           | =;= through the end of a physical line; discarded by the lexer                                                              |
* Evaluation
Owl evaluates parsed [[term-syntax-node][syntax nodes]] into [[term-value][runtime values]] in an  [[term-env][environment]]. Evaluators are created with an environment loaded with native commands. Before execution the prelude script is loaded.

The [[term-value][runtime value]]s are

#+CAPTION: Runtime Values
| kind       | contents                                      |
|------------+-----------------------------------------------|
| nothing    | no payload                                    |
| number     | 64-bit floating point number                  |
| boolean    | true or false                                 |
| text       | string                                        |
| stream     | input or output stream marker                 |
| list       | ordered values                                |
| dictionary | text keys to values                           |
| record     | fixed-key text fields to values               |
| syntax     | syntax node plus the environment it came from |
| command    | native command or closure command             |
| native     | host-provided extension value                 |

Only =nothing= and =false= are [[term-truthiness][falsey]]. Every other value is [[term-truthiness][truthy]].

** Node Evaluation
Evaluator evaluates each expression of a script in order. The value of the last statement is the resulting value. empty scripts return =nothing=.
[[term-binding][Bindings]] do not assign by themselves. Evaluating a binding returns a =syntax= value containing that binding node and its [[term-env][environment]]. [[term-command][Commands]] such as =define= and ={ }= decide how to interpret binding syntax.

[[term-symbol][Symbols]] are evaluated in this order:

1. If the symbol parses as a number, it returns a number.
2. =true= and =T= return =true=.
3. =false= and =F= return =false=.
4. Otherwise the symbol is looked up in the [[term-env][environment chain]].

[[term-string][Strings]] evaluate to text.

[[term-command][Commands]] evaluate through the [[term-call-protocol][command call protocol]]. Before resolving a command call, Owl has one shorthand rule: if a command has a symbol [[term-callee][callee]], no [[term-argument][arguments]], and no [[term-layout-body][layout body]], that symbol may evaluate directly to a literal or bound non-command value. This is why =x= reads a variable but =x 1= calls the command stored in =x=.

For any other command call, Owl evaluates the [[term-callee][callee]] expression. The callee must produce a command value. The [[term-parser][parser]] stores continuation indentation as raw [[term-argument][arguments]] on the command node. This lets indentation group command arguments in the same places where parenthesized calls can be written, for example:

#+begin_src owl
print
  +
    1
    2
    3
  "test"
  T
#+end_src

This parses like =print (+ 1 2 3) "test" T=. Continuation argument lines may contain more than one argument item, so:

#+begin_src owl
world = +
  1 2 3
#+end_src

parses =world = (+ 1 2 3)=. A binding may also put its single value on the next indented line:

#+begin_src owl
abc =
  -
    1
    9
#+end_src

When a colon follows an argument on the same line, Owl resolves the ambiguity lexically. Identifier-like argument symbols leave the colon for the outer command, so =if condition:= and =block-command name:= keep their existing block form. Operator-like argument symbols take the colon as their own command layout, so =print []:= parses as a call to =print= with one argument, the =[]= command with a colon body. Parenthesizing an operator-like symbol keeps the colon on the outer command, as in =block-command ([]):=.

The raw [[term-argument][argument]] syntax, [[term-layout-kind][layout kind]], and colon [[term-layout-body][layout body]] syntax are then passed to that command. [[term-native-command][Native commands]] and [[term-closure][closures]] decide which arguments to evaluate.

Selectors are parsed as ordinary command-shaped syntax. =a.b= parses like =field a "b"=. =xs.[0]= parses like =index xs 0=. Selectors can be chained, so =(a.b.c).d= and =a.[+ 1 2].d= nest the same =field= and =index= commands.

** Commands
There are two [[term-command][command]] kinds.

[[term-native-command][Native commands]] are host callbacks. They receive:

| input       | meaning                                          |
|-------------+--------------------------------------------------|
| environment | the [[term-caller-env][caller environment]]                           |
| arguments   | raw [[term-argument][argument]] syntax nodes                        |
| layout      | [[term-layout-kind][=NoLayout=, =ColonLayout=, or =ContinuationLayout=]] |
| body        | raw syntax nodes from the colon [[term-layout-body][layout body]]      |

Native commands are responsible for [[term-arity][arity]] checks, type checks, [[term-argument][argument]] evaluation, and body evaluation. For example, =and= and =or= [[term-short-circuit][short-circuit]] because their native implementations choose when to evaluate arguments.

[[term-closure][Closure commands]] are created by =command=, =block-command=, =fun=, =fn=, =lambda=, and
=component=. =component= is another name for =command=, and =lambda= for =fn=. A closure stores [[term-parameter][parameters]], body syntax, the environment [[term-capture][captured]] at definition time, and two flags:

| flag                 | effect                                                   |
|----------------------+----------------------------------------------------------|
| evaluatesArguments   | parameters receive evaluated argument values             |
| acceptsBlock         | calls may provide a layout body                          |

When a closure is called, the argument count must exactly match the [[term-parameter][parameter]] count. If the call provides a body and the closure does not accept one, evaluation fails.

For argument-evaluating closures, Owl creates the [[term-call-scope][call scope]] as a child of the closure's [[term-capture][captured environment]]. Each parameter is [[term-binding-value][bound]] to the evaluated argument value. This is the behavior of =fun=, =fn=, and =lambda=.

For [[term-raw-syntax][raw-syntax]] closures, Owl creates the call scope as a child of the [[term-caller-env][caller environment]]. Each parameter is bound to a =syntax= value for the raw argument node paired with the caller environment. This is the behavior of =command= and =block-command=.

A closure call also binds:

| name   | value                                               |
|--------+-----------------------------------------------------|
| block  | syntax value containing the call's body as a [[term-script][script]] |
| layout | text form of the [[term-layout-kind][layout kind]]                        |

Each is bound only when the closure body mentions that name, and never when the
closure already declares a [[term-parameter][parameter]] of that name.

The closure body evaluates in the [[term-call-scope][call scope]] and returns its last value.

** Environments And Assignment
=define= evaluates every [[term-binding][binding]] value in its body and defines that symbol in the current [[term-env][environment]]. It does not require the symbol to already exist, and it writes only to the current [[term-scope][scope]]. A symbol already bound in that same scope is an error; use =set= to update it. A symbol bound in an enclosing scope is shadowed, not an error.

The right-hand side of a binding may be an indented expression script. Its indentation supplies the boundary; each contained form evaluates in order and the script returns its last value. This applies to any expressions, commands, blocks, or values, not only control flow.

=set= mutates an existing [[term-symbol][symbol]]. In two-argument form, =set target value= evaluates the value, then assigns it to =target=.

- If =target= is a symbol, that symbol must already exist in the [[term-env][environment chain]]. The nearest scope containing the symbol is updated.
- If =target= is a selector, that is a =field= or =index= call with two arguments, Owl rewrites the container and assigns the rewritten value back through the same rule. This is what makes =set point.y 100= and =set xs.[0] 20= work, and it applies recursively through nested selectors.
- Otherwise Owl evaluates =target= as [[term-syntax-value][syntax]], requires that syntax to be a symbol, and assigns in the syntax value's [[term-capture][captured environment]].

Block form =set:= accepts only [[term-binding][bindings]]. Each binding value is evaluated and the named symbol is updated. Unlike the lower-level environment setter, the public =set= command rejects unknown symbols.

The arithmetic assignment commands =+==, =-==, =*==, and =/== require an existing numeric symbol and one numeric value. They update the existing symbol and return the new number.

*** Command Environment
Commands share state in a [[term-command-env][command environment]]. Each [[term-evaluator][evaluator]] owns one fresh command environment with the standard commands installed. The command environment is a fallback scope of the main environment, so ordinary symbol lookup and =set= can read and update its bindings.

=command-define= evaluates every [[term-binding][binding]] value in the caller environment and defines that symbol in the command environment. It does not require the symbol to already exist, and it writes only to the command environment.

The prelude uses the command environment to implement the statement form of =if= and the =else= command. =if= pushes its condition result onto a stack of pending results, and =else= pops the top of that stack, running its body only when the condition was falsey. Because =else= always follows its matching =if= block, the stack keeps nested pairs independent, so an outer =else= checks its own =if= even when an inner pair ran inside the body.

** Syntax Values
[[term-syntax-value][Syntax values]] preserve both a [[term-syntax-node][syntax node]] and the [[term-env][environment]] where that syntax was [[term-capture][captured]]. This is what makes [[term-raw-syntax][raw-syntax]] commands and macros predictable.

=eval= evaluates each [[term-argument][argument]]. If the evaluated value is syntax, Owl evaluates that syntax in its [[term-capture][captured environment]], falling back to the [[term-caller-env][caller environment]] when no captured environment is present. Non-syntax values pass through unchanged.

=parse= evaluates its text argument, parses it, and returns syntax paired with the [[term-caller-env][caller environment]].

The [[term-syntax-inspection][syntax inspection]] commands operate on syntax values:

| command        | result                                                |
|----------------+-------------------------------------------------------|
| =statements=     | list of syntax values for a script's statements       |
| =body-of=        | script syntax for the first command body matching tag |
| =command-arg=    | syntax for a command argument by index                |
| =command-symbol= | text callee name for symbol-callee commands           |
| =command-body=   | script syntax for a command body                      |
| =binding-symbol= | text name of a binding                                |
| =binding-value=  | syntax for a binding value                            |
| =eval-with=      | evaluates syntax in a child scope with one binding    |

=symbol-text= returns the text of a symbol syntax value. =define-caller-value= defines a value in the caller scope using either a symbol syntax value or a text name. These are intended for Owl-level commands that introduce names.

** Standard Control Flow
=when= evaluates one condition. If it is truthy, the body evaluates in the current environment and its last value is returned. Otherwise =nothing= is returned.

=while= evaluates one condition before each iteration. While it is truthy, the body evaluates in the current environment. The command returns the last body value, or =nothing= if the body never ran.

=pick= evaluates the condition, then evaluates only the selected branch [[term-expr][expression]].

=and= evaluates arguments left to right and returns the first [[term-truthiness][falsey]] value, or the last value when every argument is [[term-truthiness][truthy]]. With no arguments, it returns =true=.

=or= evaluates arguments left to right and returns the first [[term-truthiness][truthy]] value, or the last value when every argument is [[term-truthiness][falsey]]. With no arguments, it returns =false=.

=if=, =else=, =cond=, =not=, =do=, list literal =[]=, dictionary literal ={ }=, =record=, =for=, and the iterators =range=, =countdown=, =iter=, and =once= are not special [[term-parser][parser]] forms. They are commands defined in =owl/prelude.owl= using [[term-raw-syntax][raw syntax]], =eval=, [[term-syntax-inspection][syntax inspection]], and small native intrinsics where Owl cannot yet directly create runtime commands. The evaluator itself supplies only the primitives these are built from: =when=, =while=, =pick=, the closure constructors, and the data and syntax intrinsics.

=if= and =else= are =block-command=s defined in =owl/prelude.owl=, not evaluator special forms. Together they are expressions: =if condition:= evaluates and returns its body when the condition is truthy; a following =else:= returns the =if= result when it was truthy or evaluates and returns its own body when it was falsey. =if= pushes its condition result onto a stack in the [[term-command-env][command environment]], and =else= pops that result. This keeps nested pairs independent.

An =if=/=else= expression may be grouped wherever a single expression is required:

#+begin_src owl
answer = (if ready:
  "yes"
else:
  "no"
)
#+end_src

=cond:= evaluates =when condition:= and =| condition:= clauses in order, returning the first matching body. An =else:= clause is an unconditional fallback, so =cond= no longer needs =when true:= for its final branch.

*** Iterators
An iterator is any [[term-command][command]] that takes no [[term-argument][arguments]] and answers the next value, or =nothing= once it is spent. Nothing in the evaluator knows about them; the protocol is just that shape.

| command                    | yields                                        |
|----------------------------+-----------------------------------------------|
| =range start stop=           | =start= up to but not including =stop=            |
| =countdown start stop=       | =start= down to but not including =stop=          |
| =iter list=                  | each item of the list                         |
| =once value=                 | the value, then nothing                       |

=for name iterator:= evaluates the iterator expression, then evaluates its body once per value with =name= bound to that value in a child [[term-scope][scope]]. It returns the last body value, or =nothing= when the iterator was empty. =for-each name iterator body= is the same thing taking the body as [[term-syntax-value][syntax]], which is what =for= is built from.

=assert condition= fails when the condition is [[term-truthiness][falsey]], and otherwise returns it.

** Data Commands
Arithmetic commands =+=, =-=, =*=, and =/= require at least one argument. They evaluate all arguments as numbers and [[term-fold-left][fold left]].

Comparison commands evaluate their two arguments:

| command | comparison                                  |
|---------+---------------------------------------------|
| ~=~       | string rendering of left equals right       |
| ~<~       | numeric left is less than right             |
| ~<=~      | numeric left is less than or equal to right |
| ~>~       | numeric left is greater than right          |
| ~>=~      | numeric left is greater than or equal       |

The arithmetic assignment commands are covered under [[*Environments And Assignment][Environments And Assignment]]. =floor= returns the largest integer not greater than its argument.

Lists are values, so reading never mutates and writing answers a new list. The exceptions are =append= and =pop-front=, which rewrite a named list in place so that building a list stays linear.

| command                | result                                                             |
|------------------------+--------------------------------------------------------------------|
| =list=                   | an empty list                                                      |
| =cons value list=        | a new list with the value in front                                 |
| =first list=             | the first item; a non-empty list is required                       |
| =rest list=              | everything after the first item, or an empty list                  |
| =empty? list=            | whether the list has no items                                      |
| =nth list index=         | the item at a position                                             |
| =append-value list value= | a new list with the value on the end                              |
| =drop-front list count=  | a new list without the leading items                               |
| =append list value=      | adds to the end of a named list in place; answers =nothing=          |
| =pop-front list count=   | drops leading items from a named list in place; answers =nothing=    |
| =list-from syntax-list=  | evaluates a list of [[term-syntax-value][syntax values]] into a list of values           |

=length= returns the size of a list, dictionary, or text value.

=dict= creates an empty dictionary. =dict-put dict key value= evaluates all inputs, stores the evaluated value under the text key, and returns the dictionary value. =dict-put= also accepts records, but record keys must already be declared. =dict-get= and =field= read a text key from a dictionary or record and fail if it is missing. =index= reads a numeric list index or a text dictionary/record key. =dict-from= evaluates a list of [[term-binding][binding]] syntax values into a dictionary, and is what ={ }= is built from.

=concat= evaluates text arguments and returns their concatenation. =to-string= renders any value as the Owl source that would produce it.

The full list of [[term-native-command][native commands]], with the arguments each takes, is what =standard-commands= returns; =owl --std= prints it.

** Streams And Resources
=Stream= is a record interface defined in =owl/prelude.owl=. Its fields are command values: =open=, =close=, =read=, =read-line=, =read-all=, =write=, and =write-line=. Unsupported operations are still present in the record and raise an evaluator error when called.

=stdin= and =stdout= are =Stream= records installed in the root environment. Host-built streams are records named =Stream= too, so the =Stream?= predicate defined alongside the record recognizes them.

=open-file= returns a file-backed =Stream=. It accepts either a mode, or a path and mode. Supported modes are =r=, =rb=, =w=, =wb=, =a=, and =ab=.

=open-string= returns a string-backed =Stream=.

=with resource name:= evaluates the resource, calls its optional =open= field, creates a child [[term-env][environment]] with =name= bound to the opened resource, evaluates the body there, then calls the resource's optional =close= field in a [[term-finally][=finally= step]]. If =open= or =close= returns =nothing=, the original resource remains the value used by =with=.

Prelude helpers =close=, =read=, =read-line=, =read-all=, =write=, and =write-line= call the corresponding command fields on explicit stream values. =read= reads one byte and returns it as text, or =nothing= at end of input. =read-all= returns the remaining input as text.

** Errors
Evaluation errors are =EvaluatorError= values with [[term-source-context][source context]]. When evaluation fails, Owl adds a [[term-diagnostic-frame][diagnostic frame]] for the syntax node being evaluated, except for script nodes. Command frames use the callee text, binding frames use the binding symbol, symbol frames use the symbol text, and string frames use =string=. Reports include the primary source preview and a [[term-stack-trace][stack trace]] when frames are available.

*** Record
Records are fixed-field runtime values. They read like dictionaries, but new keys cannot be added after construction. Existing fields can be updated through =set=. Defining =record Name:= also defines a =Name?= predicate command that returns true only for records constructed by =Name=.

#+begin_src owl
record Vec3:
  x = 0
  y = 0
  z = 0

define:
  my-point = Vec3 1 2 3
  my-point2 = Vec3 1 2:
    z = 3
  my-point3 = Vec3
    1
    2
    3
print (+ my-point3.x my-point2.z)
print (Vec3? my-point)

; chaining also works (a.b.c).d
; new indexing syntax (a.[+ 1 2].d).z.e
; set a.y 100
; set xs.[0] 20
; set ys.["hello"] "world"
#+end_src

* References
<<term-argument>>Argument: one raw syntax node written after a command callee, for example =1= and =x= in =+ 1 x=.

<<term-arity>>Arity: the number of arguments a command expects.

<<term-binding>>Binding: syntax of the shape =name = value=. Evaluating a binding returns syntax; commands such as =define= decide whether it assigns.

<<term-binding-value>>Bound: stored in an environment under a symbol name.

<<term-block>>Block: an indented sequence of statements. In the AST, command blocks are stored as body syntax.

<<term-callee>>Callee: the expression at the start of a command call. It must evaluate to a command unless the no-argument variable shorthand applies.

<<term-call-protocol>>Command call protocol: the process of evaluating the callee, requiring a command value, then giving that command raw arguments, layout kind, and layout body syntax.

<<term-call-scope>>Call scope: the child environment created for one closure invocation.

<<term-caller-env>>Caller environment: the environment where a command call appears and begins evaluation.

<<term-capture>>Captured environment: the environment saved with a closure or syntax value so it can be evaluated later with the same lexical context.

<<term-closure>>Closure: a Owl command value implemented by Owl syntax. It stores parameters, body syntax, captured environment, and argument-evaluation flags.

<<term-command>>Command: a callable value. Commands may be native host callbacks or Owl closures.

<<term-command-env>>Command environment: the global fallback environment commands use for state shared across invocations. It is initialized by =command-define= and participates in ordinary symbol lookup and =set=.

<<term-diagnostic-frame>>Diagnostic frame: source location attached while an evaluation error unwinds, used to build a stack trace.

<<term-env>>Environment: a scope plus an optional parent environment. Lookup walks this chain from child to parent.

<<term-evaluator>>Evaluator: the object that owns the root environment and knows how to evaluate syntax nodes.

<<term-expr>>Expression: syntax that produces a value when evaluated.

<<term-finally>>Finally step: cleanup code that runs even if body evaluation fails. Owl uses this in =with= to close resources.

<<term-fold-left>>Fold left: combine values from left to right. For example, =- 10 3 2= computes =(10 - 3) - 2=.

<<term-group>>Group: a parenthesized expression. It holds one form, an optional [[term-layout-tail][layout tail]], and any statements that follow before the closing parenthesis.

<<term-indent>>Indentation: leading spaces or tabs at the start of a line. Owl converts indentation increases/decreases into block tokens.

<<term-layout-body>>Layout body: the indented body attached to a command call by =:=. Continuation indentation is parsed into the command's argument list instead of its body.

<<term-layout-tail>>Layout tail: the =:= suite or continuation argument block written after a form to give it a [[term-layout-body][layout body]] or extra [[term-argument][arguments]].

<<term-layout-kind>>Layout kind: how indentation was attached. =NoLayout= means no indentation, =ColonLayout= means a body followed =:=, and =ContinuationLayout= means arguments followed a newline without =:=.

<<term-lexer>>Lexer: the parser stage that turns source text into tokens.

<<term-lookup>>Name lookup: resolving a symbol by searching the current environment, then parent environments.

<<term-native-command>>Native command: a command implemented by host code. It receives raw syntax and controls its own evaluation.

<<term-parameter>>Parameter: a name declared by a closure and bound during a call.

<<term-parser>>Parser: the stage that turns tokens into syntax nodes.

<<term-raw-syntax>>Raw syntax: unevaluated syntax passed to a command as data.

<<term-root-env>>Root environment: the top-level environment created by a new evaluator.

<<term-scope>>Scope: one table of symbol bindings.

<<term-script>>Script: a sequence of statements.

<<term-short-circuit>>Short-circuit: stop evaluating operands once the result is already known. =and= stops at the first falsey value; =or= stops at the first truthy value.

<<term-source-context>>Source context: file, line, column, and source preview information attached to errors.

<<term-stack-trace>>Stack trace: the ordered list of diagnostic frames showing how evaluation reached an error.

<<term-statement>>Statement: one top-level or block-level form, optionally followed by comma-separated forms or a layout body.

<<term-string>>String: quoted text syntax. String escapes are defined in the EBNF.

<<term-symbol>>Symbol: an atom used as a name, literal keyword, command callee, or argument.

<<term-syntax-inspection>>Syntax inspection: commands that read syntax values as data, such as =statements=, =command-arg=, and =binding-value=.

<<term-syntax-node>>Syntax node: parsed AST data. Owl node kinds are script, binding, command, symbol, and string.

<<term-syntax-value>>Syntax value: a runtime value containing a syntax node and the environment it came from.

<<term-truthiness>>Truthiness: how a value behaves in conditions. Only =nothing= and =false= are falsey; all other values are truthy.

<<term-value>>Runtime value: data produced by evaluation, such as a number, text, list, dictionary, syntax value, or command.
